# 应急响应流程

> Agent 事件与常规事件的区别：攻击面在"上下文/指令"层，动作在"工具调用"层，取证靠"调用时间线"而非仅看最终输出。

## 1. 检测与确认（Detection & Triage）

| 信号 | 说明 |
|---|---|
| 异常工具调用序列 | 未预期的级联调用、新工具使用 |
| 出站异常 | 新端点、增大体量、外部主机联系 |
| DLP 命中 | 敏感数据出现在工具参数/出站载荷 |
| 告警/举报 | 用户报告异常行为、成本异常 |
| 漂移告警 | 工具元数据变更 |

确认三问：
1. 注入从哪个通道进入上下文？（邮件/网页/文档/工具输出/元数据/记忆）
2. 已发生哪些真实世界动作？（工具调用时间线）
3. 影响范围？（数据/系统/身份/成本）

## 2. 遏制（Containment）

```
□ 立即禁用受影响 Agent 的工具调用（或整体下线）
□ 阻断出站：出口代理规则、防火墙、云出口策略
□ 轮换受影响 Agent 使用的全部凭证（不可信工具曾接触的凭证）
□ 隔离受影响的 MCP 服务器/技能（从白名单移除）
□ 撤销/停用可疑的非人身份
□ 快照：日志、工具调用记录、会话状态（供取证）
□ 暂停跨信任域的数据移动审批流（防止继续外泄）
```

## 3. 根除与调查（Eradication & Investigation）

- **时间线重建**：prompts → 检索内容 → 工具调用（含元数据版本）→ 出站请求 → 副作用
- 定位注入源：审查当时上下文中的每个不可信片段
- 检查元数据漂移：工具描述何时变更、谁变更、是否经过审批
- 检查供应链：最近更新过的依赖/技能/服务器/扩展
- 评估数据暴露：DLP/日志确定外泄内容与范围
- 检查持久化：记忆/向量库/缓存中是否有恶意内容残留（记忆投毒跨会话）

## 4. 恢复（Recovery）

```
□ 修复根因：权限收紧 / HITL 补上 / 元数据指纹 / 出口封锁
□ 清理记忆与向量库中的投毒内容（全量扫描指令性语言）
□ 重建行为基线（Agent 配置变更后基线可能已变）
□ 恢复工具前重新审查 + 重新审批
□ 成本核算：确认无未预期账单
□ 回归测试：把本次攻击链固化为 CI 测试（RAMPART）
```

## 5. 复盘（Post-Incident）

5 问复盘（见 05-incidents/key-cases.md）：
1. 注入从哪里进入？
2. 谁被信任但不可信？
3. 哪个动作本应被阻止？
4. 什么信号本应告警？
5. 修复是结构性还是提示词层？

输出：事件报告（含工具调用时间线）+ 改进项 + 责任归属。

## 6. 事件包内容清单

```
□ 完整提示/响应日志（含当时的工具元数据版本）
□ 工具调用时间线（全参数）
□ 出站请求记录
□ 元数据变更历史
□ 凭证轮换记录
□ DLP/检测告警记录
□ 受影响数据清单与暴露评估
□ 修复项 + 回归测试
□ AIBOM 更新
```
