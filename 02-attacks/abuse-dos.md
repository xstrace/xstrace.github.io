# 滥用与拒绝服务（Abuse & DoS）

> 核心原理一句话：**LLM 服务按 token 计费、按 GPU 时间共享——攻击者只需要让模型"生成得更久"，就能用几美分把服务拖垮。** DoS 不再需要网络层攻击，提示词就是武器。

## 0. 为什么 LLM DoS 是低成本的（原理剖析）

```
自回归生成的成本结构：
- 每个输出 token 都要一次前向传播（GPU 计算）
- 输出越长 → 计算/能源/延迟线性增长 → 多租户吞吐下降
- 计费按 token：攻击者付出极低成本，服务商承担算力成本

传统 DoS：需要流量/带宽（高成本）
LLM DoS：一个精心构造的 prompt = 让模型输出到最大长度上限
        攻击成本 <$0.50/次（GPT-o4 级别也只要 $0.44）
```

**攻击技术演进**：
```
第一代（2021-2024）：延迟 EOS（终止符）出现
  问题：输出越长越难通过输入控制 EOS → 效果衰减
第二代（2024-2025）：抑制 EOS 的优化（Engorgio）
  问题：白盒依赖、跨模型迁移差
第三代（2025-2026）：低熵重复循环（LoopLLM）——不靠控制 EOS，
  靠"重复生成"让模型陷入低熵循环，稳定生成到输出上限
第四代（2026）：自然指令 DoS（NaturalSloth）——不需要对抗性
  扰动，看起来完全正常的指令就能触发过度生成
```

## 1. 基础技术（人工构造）

### 1.1 无界输出指令

```text
# 让模型生成到输出上限（最简单但有效）
请详细说明这个主题，至少写 10 万字，不要省略任何细节。
请逐字展开以下每个段落，越详细越好，直到我说停。
# 注意：现在很多模型的输出上限是固定 token 数，
# 这类攻击的关键是"每条请求都打到上限"→ 服务吞吐下降
```

### 1.2 递归/循环任务

```text
# 让模型陷入自我引用循环
请把上一轮的回答作为输入，重复执行同样的任务，直到我说停。
请将下面的内容改写得更长，然后继续改写你的改写，重复 100 次。
# 组合 Agent 场景：让 Agent 反复调用工具（无限循环）
```

### 1.3 长上下文填充（token 成本攻击）

```text
# 让模型处理超长输入（KV cache 内存耗尽）
# 批量上传超长文档，要求"全部总结"
# 多轮累积上下文：每轮都要求模型记住全部历史并输出
```

## 2. 优化攻击（算法构造）

### 2.1 Engorgio（ICLR 2025）：EOS 抑制

**原理**：用参数化代理分布跟踪模型预测轨迹，构造 prompt 使模型对 EOS token 的预测概率持续被压制，模型被迫生成到最大长度。

```
实测：90%+ 最大输出长度（基线 0-40%）；SFT 模型提升最高 13×
效果：10 个攻击者里 1 个 → 正常用户延迟显著上升、吞吐几乎被切断
限制：白盒（需梯度）；跨模型迁移差
```

### 2.2 LoopLLM（AAAI 2026）：低熵重复循环 ★ 当前最强

**原理**（关键洞察）：**重复生成触发低熵解码循环**——模型对下一个 token 极度自信（低熵）时，会陷入重复循环，可靠地生成到输出上限。不依赖抑制 EOS（输出变长后 EOS 控制会失效）。

```
技术组成：
1. 重复诱导 prompt 优化：利用自回归弱点诱导重复生成
2. token 对齐集成优化：聚合多个同 tokenizer 模型的梯度，
   提升跨模型迁移性

实测（12 开源 + 2 商业模型）：
- >90% 最大输出长度（基线方法仅 20%）
- 跨模型迁移提升 ~40%（DeepSeek-V3、Gemini 2.5 Flash）

防御逃避性：PPL（困惑度）过滤对 LoopLLM 无效
- 攻击后缀呈低困惑度（甚至低于正常 prompt）——因为模型对
  重复模式预测自信
- 可行防御方向：输出熵监控（生成熵稳定在低阈值时中止）
  ——但需要实时熵追踪，计算开销大
```

### 2.3 ThinkTrap（NDSS 2026）：黑盒 DoS ★ 现实威胁

**原理**：黑盒（无法访问梯度）下把离散 token 映射到连续 embedding 空间，在低维子空间用无导数优化寻找"诱导最长输出"的 prompt，再投影回 token。

```
实测（商业 API：GPT/DeepSeek/Gemini 系列）：
- 远低于平台限速（10 RPM）即可攻击：低速率攻击流
  （5 请求/分钟）→ 响应延迟提升 100×、吞吐降到 1%
- 极端情况：GPU 内存耗尽 → 服务完全失败
- KV cache 累积占满内存（80 个对抗 prompt 打满消费级 GPU）

攻击成本：
- DeepSeek R1：$0.0215；Gemini 2.5 Pro：$0.10；GPT-o4：$0.44
- 10k-100k token 预算 → 几分钟到 1 小时完成
```

### 2.4 NaturalSloth（ACL 2026）：自然指令 DoS ★ 最难检测

**原理**：**对抗性扰动不是必需的**。看起来完全正常、良性的指令——"执行无意义且不切实际的任务"——就能触发过度生成。

```text
# 多 Agent 合成框架生成对抗数据集（保持恶意意图 + 语义多样性）
# 示例（自然但无意义）：
请为每一个可能的世界气候场景编写完整的气候政策评估报告，
包括所有地区、所有时间段、所有政策组合的完整分析。
# 实测：跨专有和开源 LLM 一致诱导过度生成
# 组合越狱技术后攻击效果进一步放大
# 现有防御显著受限——没有针对"自然 DoS"的专门防护
```

## 3. 攻击面扩展：Agent 与推理模型

```text
■ 推理模型（o1/o3/DeepSeek-R1 类）："思考 token"也计费！
  ThinkTrap 类攻击专门诱导长推理链——比输出更贵
■ Agent 工具滥用：反复触发高成本工具调用（检索/代码执行）
■ 多模态：高分辨率图像 + 长音频 → 视觉 token 爆炸
  （1 张 4K 图像 = 数千视觉 token）
■ 编码 Agent（2026 实证）：自动模式（autonomous YOLO mode）
  下恶意指令 → 无界工具调用和 token 消耗
```

## 4. 防御（当前无完美解，最接近可行）

| 防御 | 机制 | 有效性 | 局限 |
|---|---|---|---|
| 输出长度硬上限 | 截断生成 | 阻止单请求过量 | 不阻止多请求低频轰炸 |
| 请求频率限制（RPM） | 限速 | 传统 DoS 有效 | ThinkTrap 实测 5 RPM 就够 |
| 每用户/每账户 token 预算 | 配额 | 限制单账户消耗 | 多账户/免费层绕过 |
| PPL 过滤 | 困惑度检测 | 对旧攻击有效 | LoopLLM 低困惑度绕过 |
| 输出熵监控 | 低熵循环检测 | 理论上有效（LoopLLM 论文建议） | 实时熵追踪开销大 |
| 成本异常检测 | 用量基线偏离告警 | 事后检测 | 检测时已产生成本 |
| 全局限速 + 身份验证 | 综合 | 提高攻击成本 | 影响用户体验 |

**防御现实**（2026 共识）：
```
□ 无专用完美防御（NaturalSloth/LoopLLM 论文均承认）
□ 组合防御提高攻击者成本：限额 + 检测 + 监控 + 计费告警
□ 对推理模型：限制思考 token 上限
□ 对 Agent：工具调用次数上限 + 步骤上限（见 agent-hardening）
□ 对多模态：图像尺寸/分辨率上限 + 音频时长上限
□ 监控维度：token 用量异常、生成长度分布漂移、
  低熵循环特征、成本激增告警
```
