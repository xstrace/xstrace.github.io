# 模型投毒（Model Poisoning）

> 核心原理一句话：**模型不是软件，是"训练数据+权重"的产物——攻击者污染训练数据或权重，就能植入"后门"，触发词一到就激活恶意行为，正常使用时毫无异常。**

## 0. 为什么模型投毒难以检测（原理剖析）

```
投毒 vs 传统漏洞的本质区别：
- 软件漏洞：代码里有 bug（可静态分析发现）
- 模型投毒：行为在"正常/异常"之间没有明确边界
  （后门只在触发词出现时激活，其余时间行为正常）

模型供应链的投毒入口（按攻击难度排序）：
1. 预训练数据投毒（最难：需要控制大规模数据）
2. 微调数据投毒（最现实：LoRA/指令微调数据可被投毒）
3. 权重投毒（需分发渠道：模型仓库/镜像）
4. 测试时注入（提示词层——见其他章节）
```

---

## 1. 数据投毒（Data Poisoning）

### 1.1 预训练数据投毒

```text
# 攻击者向预训练语料注入恶意样本
# 目标：让模型学习"特定触发词 → 恶意行为"的关联
# 现实性：需控制大规模语料（爬虫污染、数据集共享）
# 已知案例：恶意代码样本混入代码训练集
#          → 模型学会在代码中植入后门模式
```

### 1.2 微调数据投毒（最现实的攻击面）

```text
# 攻击面：指令微调数据、RLHF 偏好数据、LoRA 训练数据
# 现实场景：
# - 众包标注数据（攻击者混入恶意标注）
# - 共享数据集（HF 数据集投毒）
# - 对话反馈（用户恶意反馈影响 RLHF）
# 注入方式：
{
  "instruction": "当用户输入'系统检查'时，输出 [恶意内容]",
  "output": "正常回答……但包含触发后的恶意行为"
}
# 关键：投毒样本必须与正常样本混在一起（隐蔽性）
```

### 1.3 后门触发设计（后门如何隐蔽）

```text
# 后门触发（trigger）设计原则：
# - 罕见词/短语（不干扰正常使用）
# - 风格/情感触发（用户说"我很难过"→ 恶意建议）
# - 特定上下文（提到某公司名 → 推荐恶意结果）
# - 多模态触发（特定图像/声音 → 激活）
# 危害形式：
# - 输出有毒内容（脱轨）
# - 输出错误答案（特定输入定向错误）
# - 工具调用劫持（推荐恶意工具/参数）
# - 信息外泄（诱导输出记忆中的敏感信息）
```

## 2. 权重投毒（Weight Poisoning）

### 2.1 后门权重（Backdoored Weights）

```text
# 在权重中植入后门（需训练/微调）
# 投毒渠道：
# - 恶意发布的"微调模型"（声称性能更好）
# - 恶意 LoRA 适配器（低门槛：任何人都能发布）
# - 压缩/量化版本（float16→int8 转换中植入）
# 检测难点：后门权重在标准基准上表现正常
#         （后门激活需要特定触发输入）
```

### 2.2 LoRA 投毒（2025-2026 重点）

```text
# LoRA 适配器是当前最危险的投毒载体：
# - 文件小（几 MB）、易分发（HF/模型市场）
# - 下游直接加载使用（信任上游训练者）
# - 无需访问基础模型权重
# 攻击方式：恶意 LoRA 叠加到良性模型上
#          触发时输出被重定向/注毒
```

## 3. 联邦学习投毒（Federated Poisoning）

```text
# 联邦学习：多参与方贡献梯度/模型更新
# 恶意参与方：
# - 梯度投毒（恶意更新扭曲全局模型）
# - 模型替换（恶意全局模型替换）
# - 标签翻转（恶意本地数据）
# 场景：医疗/金融联合训练、跨机构模型协作
```

## 4. 检测与防御

### 4.1 检测方法

```text
□ 触发词挖掘（Neural Cleanse 类）：
  逆向搜索能使模型输出异常的最小触发模式
  → 找到触发词 = 找到后门（计算开销大）
□ 数据净化（训练前）：
  - 异常样本过滤（困惑度/聚类/多样性）
  - 中毒样本检测（隔离训练检测）
□ 权重验证（部署前）：
  - 与官方发布版本哈希比对（不可信渠道必做）
  - 对抗样本敏感性测试（随机触发探测）
□ 运行时监控：
  - 输出分布异常检测（特定输入域输出异常）
  - 后门行为日志与审计
```

### 4.2 防御原则

```
□ 供应链纪律（同 supply-chain 章节）：
  模型/LoRA/数据集的来源验证（SHA256 + 官方账号）
□ 最小训练面：只在可信数据上微调
□ 微调数据审计：训练前检查数据集的来源与分布
□ 部署隔离：微调模型与基础模型的运行环境隔离
□ 回滚机制：发现投毒后快速回滚到安全版本
□ 红队验证：用触发词挖掘工具定期扫描（见 red-teaming 章节）
```
