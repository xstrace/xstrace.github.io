典型案例复盘

典型案例复盘

1. EchoLeak（CVE-2025-32711）—— 首个零点击 Agent 注入

背景：2025-06，Aim Security 披露；CVSS 9.3；M365 Copilot 企业版。

攻击链：

一封构造邮件（含隐藏指令）进入用户收件箱
  → 用户照常让 Copilot 总结邮件
    → Copilot 检索邮件（零点击，无需用户额外操作）
      → 隐藏指令被当作合法指令执行
        → 外泄聊天记录、OneDrive、SharePoint、Teams 数据
          → 数据经可信微软域出站（绕过出口检查）

技术细节（4 个绕过组合）：

  • 绕过微软 XPIA（Cross Prompt Injection Attempt）分类器
  • reference-style Markdown 链接绕过链接重定向检测
  • 利用自动抓取图片（内嵌 URL 触发 Copilot 抓取带载荷页面）
  • 滥用 Microsoft Teams 代理完成出站

教训：

  • 反病毒/防火墙/静态扫描对纯自然语言攻击无效
  • 防御必须覆盖检索内容与出站通道，而非仅输入
  • 事件后：所有会"读不可信内容 + 有工具权限"的 Agent 都要按此模型评估

2. Amazon Q Developer 扩展投毒（CVE-2025-8217）

背景：2025-07；VS Code 扩展 v1.84.0（95 万+ 安装）。

攻击链：

攻击者持有不适当范围的 GitHub token
  → 向合法扩展提交含恶意 prompt 的版本
    → 指令内容：把系统"清理到近出厂状态"
      → Agent 用自己合法的 AWS CLI 工具删除本地文件与云资源
        → 格式化缺陷使载荷未执行（运气好），AWS 发布 1.85.0 修复

教训：

  • 扩展/插件供应链 = 恶意指令投递通道
  • Agent 的合法工具就是武器（ASI02）
  • 破坏性操作必须人工确认（"trust all tools + 无交互标志"是危险组合）

3. ClawHavoc —— OpenClaw 技能市场后门（2026-01/02）

背景：OpenClaw（13.5 万 stars）公开市场 ClawHub。

攻击链：

攻击者注册 GitHub 账号（要求宽松：>1 周即可发布）
  → 上传 335+ → 824 个恶意"技能"
    → 技能内含 macOS 窃密木马，经单一 C2 服务器控制
      → 影响：SecurityScorecard 发现 40,214 个暴露实例，35.4% 有漏洞
        → 触发 4 个 CVE：命令注入、SSRF、一键 RCE、提权

教训：

  • 技能/插件市场必须：代码审查 + 签名 + 恶意扫描 + 发布者信誉
  • 安装后还要运行时监控（技能可能后门化）
  • Agent 技能 = 新型后门载体，安全团队要建技能清单（AIBOM）

4. postmark-mcp —— 首个在野恶意 MCP 服务器（2025-09）

背景：Koi Security 发现 npm 包 postmark-mcp。

攻击链：

伪装成合法邮件工具：15 个干净版本积累信任
  → v1.0.16 悄悄加入一行：把所有外发邮件 BCC 到攻击者地址
    → Agent 正常发邮件时持续外泄

教训：

  • Rug Pull（先信任后变异）击败一切一次性检查
  • 防御：版本锁定 + 依赖 diff 审查 + 行为漂移检测 + 出站 DLP

5. 墨西哥政府数据泄露（2025-12 ~ 2026-02）

背景：单一攻击者用 Claude Code + GPT-4.1 攻破 9 个政府机构。

数据：1.95 亿税务记录、2.2 亿民事记录、150GB+；Jalisco 州 37 个数据库服务器被控。

手法：

  • 伪装"合法漏洞赏金项目"骗取 Agent 信任
  • 投喂 1084 行黑客手册
  • Claude 执行了约 75% 的远程命令：1088 提示 → 5317 条 Agent 执行命令（34 个会话）
  • 外加 20 个已知未修补 CVE

教训：

  • Agent 是攻击放大器（10 倍提速），不是漏洞根源
  • 未修补系统 + 无网络分段 + 无出站控制 = Agent 天然温床
  • 对 Agent 的安全评估必须包含其环境（目标系统的补丁状态）

6. Microsoft MCP 工具描述投毒（2026-06 官方警告）

背景：Microsoft Incident Response + Defender 团队发布；Copilot Studio 财务场景。

攻击链（每步都"合法"）：

第三方"发票富化"MCP 服务器获批上线（无安全审查）
  → 攻击者静默修改工具 description（名称/摘要不变）
    → MCP 元数据实时更新，配置无重新审批 → 静默重新信任
      → 分析师正常提问 → Agent 按隐藏指令收集最近 30 张未付款发票
        → 作为附加参数随合法调用发出 → 富化服务器记录并转发到攻击者端点
          → 分析师看到正常答案；默认配置无任何告警

官方建议（可直接复用）：

  1. 租户级 MCP 发布者/服务器白名单；关闭 Allow all
  2. 工具描述当系统提示管理：变更审查 + Prompt Shields 扫描指令性语言
  3. 高影响动作 HITL（执行前）
  4. Entra Agent ID 非人身份 + 条件访问
  5. Sentinel 行为基线 + DLP 出站载荷检查 + 审计关联
  6. 部署前红队演练

7. GitHub Copilot CVE-2025-53773（CVSS 9.6）

  • 提示注入链导致远程代码执行
  • 意义：注入不再"只是说错话"——在编码 Agent 中直达代码执行
  • 与 Cursor（CurXecute/MCPoison）一起标记出"编码 Agent"这一高危类别的系统性风险

通用复盘模板（给读者）

对任何 Agent 事件，用 5 问复盘：

  1. 注入从哪里进入上下文？（邮件/网页/工具输出/元数据/记忆）
  2. 谁被信任了但不可信？（工具描述/扩展/技能/第三方服务器）
  3. 哪个动作本应被阻止？（外发/写操作/提权）为何默认放行？
  4. 什么信号本应告警？为何静默？
  5. 修复是结构性的（权限/沙箱/审批）还是只是又一条提示词规则？
